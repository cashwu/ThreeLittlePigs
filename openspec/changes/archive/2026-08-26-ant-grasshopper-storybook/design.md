## Context

目前的產生流程是：`eng.md`（每個非空白行 = 一句）→ `generate_audio.py` 解析 → `lines.json`（扁平的 `[{en, zh}]`）→ edge-tts 產生英文與中文音檔並捕捉 word boundary → 把 `LINES` 與 `TIMINGS` 內嵌進 `index.html`。網頁必須能用 `file://` 直接開啟，所以資料一律內嵌，不做 runtime fetch。

新內容是《The Ant and The Grasshopper》整本繪本，12 頁、50 句。與舊內容的關鍵差異：

1. **內容有頁的層級**。舊資料是扁平的一維陣列，新資料需要「頁 → 句」兩層。
2. **顯示換行與句子邊界不一致**。`story.md` 會刻意把部分句子拆成 2-3 個顯示行；反過來，同一行也可能橫跨兩個句子的邊界（例如 p.12 的 `he cried. "And I'm starving, too!`）。換行要保留在畫面上，但不能影響音檔切割。
3. **`index.html` 的現值與模板的現值不一致，而本次會由模板重新產生**。commit `4114ad5` 的四項 UI 調整全部只手改在 `index.html`，從未回寫 `generate_audio.py` 的 HTML 模板；`git show --stat 4114ad5` 顯示只有一個檔案被改動。目前模板與 `index.html` 的差異有四處：速度按鈕（模板為「慢2倍」0.33／「慢1倍」0.5／「正常」0.75，`index.html` 為「慢慢」0.33／「正常」0.5）、預設播放速度（模板 0.75，`index.html` 0.5）、中文播放按鈕（模板未註解，`index.html` 已註解）、`.zh-text` 的 `margin-left: 50px`（模板沒有，`index.html` 有，是為了補償中文按鈕消失而加的對齊）。這四項若照「維持現況不變」直接沿用模板，重新產生後都會倒退。

另有一類不同性質的改動：模板與 `index.html` 的 `<title>`、`<h1>` 與副標**兩者相同**，皆為《Three Little Pigs》與 `Ryan - pig 2`。它們不是模板落差、不會倒退，而是本次要一併改為新繪本的內容。
4. **中文不再發音**。`index.html` 的中文播放按鈕已註解，但腳本仍在產生中文音檔，規格與實作已經有落差，這次一併收斂。

約束：
- 網頁必須維持單檔、可 `file://` 開啟、無外部相依。
- 播放/暫停切換、逐字 karaoke、速度切換對使用者呈現的行為不能變（但模板需回寫成 `index.html` 的現值才能達成）。
- edge-tts 未安裝在系統 Python，需透過 uv 在執行時載入該套件。

## Goals / Non-Goals

**Goals:**

- 用 12 個頁碼 tab 切換，一次只顯示一頁的句子。
- 音檔以「完整句子」為單位，語氣自然完整。
- 畫面保留 `story.md` 定義的顯示換行，維持易讀的跟讀節奏。
- karaoke 逐字高亮在跨換行的句子上仍然正確對齊。
- 資料來源維持人類可讀、可手改，且有 fail-fast 的一致性檢查。
- 重新產生 `index.html` 後，使用者可見的行為與現在的 `index.html` 一致，不因模板落後而倒退。

**Non-Goals:**

- 不做整頁連續播放、不做上下頁箭頭或滑動手勢。
- 不做插圖、不做中文語音。
- 不保留舊的《Three Little Pigs》內容作為第二本書。
- 不改變速度按鈕呈現給使用者的選項與標籤（「慢慢」0.33／「正常」0.5、預設「正常」）。

## Decisions

### 以句號分句，換行只保留為顯示資訊

一句 = 一段音檔 = 一個播放按鈕。繪本的換行改以 `<br>` 呈現在同一個句子卡片內。

段落邊界（空行）一律強制斷句，標點規則只在段落之內套用。

這條規則的用途是**安全網**：防止未來出現「某段以句尾標點結束、下一段以小寫字母開頭」的內容時被誤併成一句。就本次編寫內容的段落邊界（例如 p.5 的 `through the long grass.` 之後接 `"Why do you bother to work so hard?"`）而言，段落邊界同時也滿足標點規則，因此段落規則預期不會改變本次的分句結果。實際的段落邊界數由完成的 `story.md` 決定；驗證方式因此是「每一處段落邊界都產生了句界」，而非寫死某個數字，也不需要為此人工改動 `story.md`。

替代方案：**照每個顯示行**（每個換行一句）語氣會在句中斷掉，例如 `All summer long, the grass grew tall,` 會單獨成為一段音檔；**照空行分段**則一段音檔太長，小朋友不易跟讀。以句號分句是兩者的折衷，也讓 TTS 有完整的句子語調。

因此每個句子的資料形狀是 `en_lines`（顯示用的行陣列）而非單一字串。送給 TTS 的文字則是把 `en_lines` 以單一空白串接的結果。

`en_lines` 的每一個元素 SHALL 為已去除首尾空白的非空字串。這不是潔癖：分句規則會在某個顯示行的中間切開（`he cried. "And I'm starving, too!`），切點兩側的空白會落到某個 fragment 上；若前導空白被保留，瀏覽器端的 `split(/\s+/)` 會多產生一個空字串 token（實測 `[" \"And I'm starving, too!"].join(' ').split(/\s+/)` 得到 5 個元素，首個為空字串），token 數與 `timings` 長度差 1，該句就靜默退回無高亮。Python 的 `str.split()` 會自動去除首尾空白，所以腳本端的任何自檢都看不到這個不對稱。

### 用「句尾標點 + 空白 + 大寫或引號」的規則自動分句

分句規則：段落內先把換行換成標記保留，再以 regex 在「`.`、`!`、`?`（可後接一個右引號）+ 空白字元 + 接續字元為大寫字母或左引號」處切開。切完後再依標記還原成顯示行。

引號一律使用 ASCII 直引號 `"` 與 `'`。`story.md` 編寫時 SHALL 不使用彎引號，否則 `he cried. "And` 這個關鍵句界不會被切開、p.12 會變成 6 句，雖然逐頁 fail-fast 會擋下來，但錯誤訊息指不到真正原因。因此 `story.md` 需要一條「無彎引號」的檢查。

這條規則刻意**不**在「句尾標點 + 小寫開頭」處切開，因為對話加上敘述屬於同一句：

- `"Why do you bother to work so hard?"` / `asked the grasshopper.` → 下一個字 `asked` 是小寫，不切，維持一句。
- `"You are just wasting your time!"` / `he laughed.` → 同理不切。

而真正的句子邊界都會被切到，包含出現在行中間的：

- `he cried. "And I'm starving, too!` → `.` 後接空白與 `"`，切開。
- `...in the meadow.` / `She worked hard...` → `.` 後接換行與大寫 `S`，切開。

替代方案：用 NLP 斷句套件（如 nltk 的 punkt）會引入額外相依，且對繪本這種乾淨、無縮寫的文本沒有額外好處。手工在來源檔標註句子邊界則讓來源檔不再像一般文章，後續維護也更困難。

### `story.md` 為英文來源，`story_zh.json` 為中文來源，`story.json` 為產出的中介檔

`story.md` 用 `## p.2` 這種頁碼標題分頁，內文由本變更編寫為完整、連貫的《The Ant and The Grasshopper》英文故事，並保留作者設定的顯示換行與空行。故事 SHALL 採用 12 頁、50 句的既定結構，並保留 Implementation Contract 與 examples 指定的關鍵句。中文翻譯放在 `story_zh.json`，結構是 `{"2": ["...", "..."], "3": [...]}`，key 為頁碼字串，value 為該頁句子的中文翻譯陣列，順序對應分句結果。

腳本在分句後檢查每一頁的英文句數與中文句數是否相等，不相等就印出頁碼與兩邊數量並以非零狀態結束，不產生任何檔案 —— 沿用既有的 fail-fast 精神，只是把檢查從全域改成逐頁，錯誤訊息能直接指出是哪一頁對不上。

替代方案：把中文寫死在 `generate_audio.py` 裡（目前作法）在 50 句時會讓腳本變得很難讀；把中文寫進 `story.md` 則會混合兩種權威來源，也讓自動分句規則要處理中英混排。

`story.json` 是分句後的產物（頁 → 句 → `{en_lines, zh}`），供除錯與檢視用，實際渲染資料仍內嵌進 `index.html`。它同時是驗證分句結果的唯一介面 —— 不另外新增只解析不產音的 CLI 旗標，避免同一個能力有兩套實作與兩套語意。

### 音檔命名採頁面內流水號 `en_pNN_MM.mp3`

頁碼補零兩位（`p02`、`p10`、`p16`），頁內序號補零兩位（`01`、`02`）。例如 p.2 的第一句是 `audio/en_p02_01.mp3`。

替代方案：沿用全域流水號較簡單，但只要修改中間某一頁的文字造成句數變動，後面所有頁的檔名都會位移，整批音檔都要重產。頁面內流水號把影響侷限在該頁。

代價是會產生孤兒檔：某頁句數從 7 降到 6 時，`en_p12_07.mp3` 會永遠留在 `audio/` 裡，網頁不會壞、也沒有任何檢查會發現。因此腳本在成功產生後 SHALL 刪除 `audio/` 中所有不屬於本次產生結果的音檔（比對條件為「是否在本次產生的檔名集合中」，而非比對 `en_` 前綴），使 `audio/` 的內容恰等於本次產生的集合。舊繪本的 9 個中文音檔也由這一步清除，不另設人工刪除步驟。驗收條件因此寫成「恰等於本次產生集合」而非寫死某個數字。

不再產生中文音檔：中文播放按鈕已註解，產生它只是浪費時間與磁碟。

### `index.html` 一律由 `generate_audio.py` 模板產生，手改需回寫模板

`index.html` 是產出物，不是來源。commit `4114ad5` 直接手改 `index.html` 而未回寫模板，造成兩者分歧；本次重寫模板時 SHALL 把 `index.html` 目前的四項現值寫進模板：兩顆速度按鈕與其標籤、預設 `playbackRate` 0.5、中文播放按鈕以 HTML 註解輸出、`.zh-text` 的 `margin-left: 50px`。另需把 `<title>` 與 `<h1>` 改為新繪本並刪除副標 `Ryan - pig 2`（新繪本無對應角色）—— 這一項不是回寫現值，因為模板與 `index.html` 的標題同為舊值。

替代方案：把 `index.html` 改為手工維護、腳本只產生資料檔，會讓網頁需要 runtime fetch，違反可 `file://` 直接開啟的約束。

### tab 切換以顯示/隱藏既有 DOM 實作，並在切頁時停止播放

12 頁的句子卡片一次全部渲染進 DOM，切 tab 只是把非當前頁的容器設為 `display: none`。50 張卡片對瀏覽器毫無壓力，事件繫結方式維持不變。

DOM id 從現況的全域流水號 `en-words-<globalIdx>` 改為頁內定位 `en-words-p<頁碼兩位>-<頁內序號兩位>`（例如 `en-words-p12-07`）。沿用全域流水號會需要一個跨頁的計數器，而那正是下一節要消除的東西；改為頁內定位後，id 直接由 `PAGES` 的頁碼與序位推得，唯一性不依賴任何計數器。

切頁時呼叫既有的 `stopCurrent()`：否則使用者切走之後，看不見的那一頁仍在播音、按鈕仍停在暫停圖示，狀態與畫面不一致。

tab 列 SHALL 以 `position: sticky; top: 0` 固定在視窗頂端，且切換 tab 後 SHALL 把捲動位置回到該頁頂端。tab 列 SHALL 具有不透明背景，使捲動中的白色句子卡片不會從 tab 文字底下透出而與 28px 英文字重疊。tab 列本身 SHALL 不換行、以 `overflow-x: auto` 橫向捲動：12 個 tab 在手機寬度下若改以換行容納，sticky 的列會折成 2-3 行並長期占用 viewport 高度，與「28px 大字、一頁最多 7 張卡」的可讀性目標互相拉扯；橫向捲動讓 sticky 列恆為一行高。p.12 有 7 張卡片、英文 28px 且多行，在手機上必然超過一個 viewport；若 tab 列只在文件流最上方，小朋友唸到該頁最後一句想換頁時必須先捲回頂端才找得到 tab，而切到只有 2 張卡的 p.16 時捲動位置也不會自動重設。

替代方案：切 tab 時重建 DOM 會讓事件繫結與播放狀態管理複雜化，沒有相應好處。

### karaoke 的 `<span>` 索引跨 `<br>` 連續編號

edge-tts 的 word boundary 是針對「整句」產生的，所以 `<span>` 的索引必須以整句為範圍連續編號，不能每個顯示行各自從 0 開始。作法是先把 `en_lines` 攤平成單一 token 陣列（把 `en_lines` 以空白串接後再以空白切分），逐一產生 `<span>`，再在原本的換行位置插入 `<br>`。

fallback 的觸發條件與影響範圍（token 數與 timing 數不符就整句不切 span、不高亮、但仍可播放、不影響其他句子）保留不變，但呈現方式改為保留 `<br>` 換行，而非現況的單一字串 —— 這次內容有 `hadn't`、`I'm`、`"Why` 這類含縮寫與引號的 token，edge-tts 的切詞未必與空白切分一致，fallback 讓個別句子失準時不影響其他句子。

### word boundary 併入 `PAGES`，不保留獨立的全域 `TIMINGS`

每個句子的 word boundary 陣列直接掛在該句子的物件上，與 `en_lines`、`zh`、`audio` 並列，不再有以全域句子索引定位的獨立 `TIMINGS` 陣列。

理由是消除兩套索引空間並存的靜默錯位風險：`PAGES` 以「頁 + 頁內序號」定位，全域 `TIMINGS` 以「跨頁流水號」定位，渲染時的流水計數器只要錯一格，karaoke 就會對到別句的時間軸。既有的 token 數與 timing 數比對只在兩句字數剛好不同時才擋得下來，字數相同時就是靜默高亮錯字。合併之後，加上 DOM id 一併改為頁內定位，跨頁流水計數器在渲染路徑上完全消失，錯位在結構上不可能發生。

替代方案：維持與現況相同的獨立 `TIMINGS`（原本的理由只是「格式與現況相同」），但現況是扁平的一維資料、本來就只有一套索引，新資料有兩層結構，沿用反而引入了現況沒有的風險。

## Implementation Contract

**Behavior**

- 開啟 `index.html`（含 `file://`）時，畫面由上而下是：標題區（`<h1>` 為 `The Ant and The Grasshopper`，無副標）、12 個頁碼 tab（`p.2 p.3 p.4 p.5 p.6 p.7 p.8 p.10 p.12 p.14 p.15 p.16`）、速度控制列、句子卡片。預設選中 `p.2`，只顯示 p.2 的句子卡片。
- tab 列在頁面捲動時維持可見（sticky 於視窗頂端）。
- 點擊任一 tab：該 tab 變為選中樣式、前一個 tab 取消選中、只有該頁的句子卡片可見、捲動位置回到該頁頂端，且任何正在播放或暫停中的音訊停止、其按鈕回到 ▶、其 karaoke 高亮清除。
- 每個句子卡片顯示：頁內序號、英文播放按鈕、依 `story.md` 顯示換行排版的英文句子、下方灰色中文翻譯。中文播放按鈕維持 HTML 註解狀態、頁面上看不到。
- 播放/暫停切換、單一播放（開新的就停舊的）、逐字高亮、暫停時高亮保留、速度切換（慢慢 0.33／正常 0.5，預設正常）行為與目前的 `index.html` 完全相同。
- 頁面任何位置不再出現 `Three Little Pigs` 或 `Ryan - pig 2`。

**Interface / data shape**

- `story.md`：以 `## p.<n>` 標題分頁，標題下方為該頁編寫的英文故事文字，段落間以空行分隔，引號一律為 ASCII 直引號。
- `story_zh.json`：`{"<頁碼字串>": ["<中文句>", ...], ...}`。
- `story.json`（產出）：
  ```json
  [{"page": "2", "sentences": [{"en_lines": ["Once upon a time,", "a little ant lived in a beautiful meadow."], "zh": "..."}]}]
  ```
- 音檔：`audio/en_p<頁碼兩位>_<頁內序號兩位>.mp3`。
- 產出順序 SHALL 為：解析與分句 → 逐頁英中句數檢查 → 檢查通過後立即寫出 `story.json` → 把全部音檔產生至 `audio/` 內的 staging 目錄 → 50 句全部成功後發布正式音檔 → 寫出 `index.html` → 清除孤兒檔。`story.json` 先於音檔寫出，使分句結果在不需要跑完 50 次 TTS 的情況下即可檢視。清除孤兒檔排在寫出 `index.html` **之後**：兩者之間沒有資料依賴（`index.html` 只引用本次產生的檔名集合），而反過來排會留下一個具破壞性的窗口 —— 舊音檔已刪、新 `index.html` 尚未寫出時，舊的 `index.html` 會指向已不存在的音檔。
- DOM id：`en-words-p<頁碼兩位>-<頁內序號兩位>`。
- `index.html` 內嵌單一 JavaScript 變數 `PAGES`：結構同 `story.json`，但每個句子物件額外帶 `audio`（該句音檔檔名）與 `timings`（`[{word, offset}]` 陣列）。不存在獨立的全域 `TIMINGS` 變數。

**Failure modes**

- 任一頁的英文句數與中文句數不符 → 印出 `Page p.<n>: <英文句數> English sentences but <中文句數> Chinese translations`，以非零狀態結束，不產生任何音檔、`story.json` 或 HTML。
- `story_zh.json` 缺少 `story.md` 中出現的頁碼 → 同樣以非零狀態結束並指出缺少的頁碼。
- 單一句子的空白切分 token 數與 word boundary 數不符 → 該句退回**保留 `<br>` 換行的**純文字顯示、不切 span、無高亮，播放仍正常，不拋錯、不影響其他句子（靜默）。注意現況 `index.html` 的 fallback 是 `enHtml = line.en`（單一字串、無換行資訊），在新資料下不可原樣沿用 —— 那會把 `en_lines` 併成一行而丟失顯示換行，違反「畫面保留 `story.md` 顯示換行」這項 Goal。
- 50 次 edge-tts 請求循序寫入 `audio/` 內的 staging 目錄；任一次串流因連線中斷或服務節流而失敗時，暫存目錄由 Python 清除，正式音檔與 `index.html` 均不變。只有 50 句全部成功後，腳本才以同檔案系統的 `Path.replace()` 逐檔發布正式音檔，再寫出 `index.html` 並清除孤兒檔。`story.json` 仍會先寫出，復原方式是直接重跑整支腳本；每次執行都重新產生全部音檔，因此重跑是 idempotent 的。

**Acceptance criteria**

- `story.md` 解析後為 12 頁，各頁句數依序為 4, 4, 3, 5, 3, 5, 5, 4, 7, 5, 3, 2，合計 50 句。
- `audio/` 的內容恰等於本次產生的英文音檔集合：每一頁每一句各一個 `en_pNN_MM.mp3`，且沒有任何中文音檔、沒有任何舊的全域流水號音檔、沒有任何孤兒檔。

**Scope boundaries**

- 範圍內：`generate_audio.py` 改寫（含 HTML 模板回寫）、`story.md` 與 `story_zh.json` 新增、`eng.md` 與 `lines.json` 刪除、`audio/` 重新產生、`index.html` 重新產生。

## Risks / Trade-offs

- **自動分句規則在未來新增內容時可能誤判**（例如出現 `Mr.` 這類縮寫，或以小寫字母開頭的新句子）→ 每頁的英中句數 fail-fast 檢查會在誤判時立刻擋下來並指出頁碼；`story.json` 也可直接檢視分句結果確認。
- **編寫時混入彎引號會讓句界失效，且錯誤訊息指不到真正原因** → `story.md` 加一條「無彎引號」的檢查，在建立來源檔的階段就擋下來。
- **edge-tts 的切詞與空白切分不一致，導致部分句子失去 karaoke 高亮**（`hadn't`、`I'm`、含引號的 token 風險最高）→ 沿用既有的 per-sentence fallback，失準只影響單句；產生後比對每句的 token 數與 `timings` 長度，記錄失準句數，偏多再考慮調整 tokenization。
- **50 句循序 TTS 請求，產生時間比舊的 9 句長很多，且中途可能失敗** → 不再產生中文音檔已省下一半工作量；先在 staging 產生完整集合，失敗時保留正式音檔與 `index.html`，重跑仍為 idempotent。
